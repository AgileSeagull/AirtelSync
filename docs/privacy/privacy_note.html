02Controls built into the design

Consent (DPDP §§ 5–6)

  • Versioned notice in English or Hindi before any document: what, why, who sees it, how long, rights, grievance contact.
  • Separate purposes: KYC is required; WhatsApp updates and marketing start unticked. Without the WhatsApp opt-in, updates stay in the app.
  • Withdrawing consent before e-sign deletes the documents at once.

Data minimisation

  • The advisor never asks for Aadhaar, PAN or bank details. If an owner pastes them, they are stripped (with phone numbers and UPI IDs) before the text reaches the LLM.
  • GSTIN is masked wherever it is shown (27ABC•••••••1Z5): screens, console free text and the tool results the LLM sees.

Protection of documents

  • Images encrypted at rest (Fernet: AES-128-CBC with HMAC-SHA256) and purged after the decision; only extracted fields and a fingerprint remain.
  • Every KYC verdict lists its reasons; unclear cases go to a person rather than being rejected automatically.

Access and accountability

  • Role-based console: partners see only the leads routed to them; only sales staff can decide KYC reviews.
  • A partner can help in assisted mode only after the owner receives a 4-digit code and chooses to share it.
  • Audit log of consent given and withdrawn, uploads, DigiLocker fetches, verification, review decisions, e-sign and assisted access.

Safe use of AI

  • The LLM can only call five server-side tools. A guard rejects any reply naming a price or product no tool returned, and the server re-prices every quote, so neither the model nor the browser can set a price. Owner messages are treated as data, not instructions, to limit prompt injection.
